# 行程怎么排

行程表失败的地方从来不是"没安排"，而是**没留缓冲**和**和已有安排撞了**。

## 步骤

1. **先把硬约束问全**：出发/返回的确定时间、必须赴的约（谁、几点、在哪）、不可动的已有日程。缺一项就先问，不要排完再让人自己改。
2. **查冲突**：`calendar_list` 拉覆盖日期内的全部日程，逐个比对。**冲突要显式列出来**（"周三 14:00 的会和高铁 14:20 发车冲突，中间需要 40 分钟到站"），不要悄悄把会挪掉。
3. **按天排，每项四件**：时间块 / 地点 / 路上要多久 / 缓冲多少。
   - 缓冲默认按路上时间的 30% 加，跨交通枢纽的按 1 小时起；
   - 一天不超过 3 个"必须准时"的点，多了就提醒用户这天的排法有风险。
4. **外部信息要有出处**：票价、班次、开放时间用 `web_search` / `web_fetch` 查，写明查询日期。查不到的写「需现场确认」，**不写一个看起来合理的数**。
5. **落盘**：`write` 成 `行程-<目的地>-<日期>.md`。只有时间已确定且用户点头的条目才 `calendar_create`；候选项留在文件里，别塞进日程。

## 红线

- 不代替用户取消或改动已有日程；
- 天气、票价这类会变的信息，标注"截至 X 日查询"，并提醒临行前复核；
- 预算类数字没有依据就不给，不编一个"大概三千左右"。

## 忌词

「视情况而定」「灵活安排」—— 行程表里这两个词等于没排，要么给时间要么给决策点。
