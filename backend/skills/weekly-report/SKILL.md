# 周报怎么做

周报的读者是**别人的上级**，所以它的评价标准不是"写全了"，而是"三分钟能看懂这周做了什么、下周要做什么、哪儿卡住了"。

## 步骤

1. **先问清三件事**（缺哪件问哪件，别自己猜）：给谁看、要不要落盘成文件、有没有固定格式。用户说过"按老格式"时，先用 `kb_search` 找历史周报，照它的结构来 —— 格式一致比内容漂亮重要。
2. **取材，按这个优先级**：
   - 本周的对话与任务记录（用户亲手说过的、后台任务产出的）；
   - `kb_search` 检索本周文档/纪要；
   - 只在用户明确要求时才 `web_search` 补充外部背景。
   每条要点都要能指回来源；指不回的**不要写进周报** —— 周报里的一句编造，会被当成事实往上转述。
3. **按 `references/checklist.md` 自查一遍**再落笔（那份清单列的是常被漏掉的项和忌词）。
4. **落盘**：默认 Markdown，用 `write` 写到工作目录；用户要 Word 时用 `generate_document`，要 PDF 则先生成 Word，再用 `convert_document` 转换（需本地引擎）。修改已有 Word 周报先 `read_document` 再 `edit_document`，保留原文结构。文件名带日期（例：`周报-2026-10-17.md`），生成后**明确说出文件在哪**，不要只说"写好了"。
5. 回复里只给三段以内的摘要 + 文件路径。周报本身不要在对话里重复一遍，太长用户不会看。

## 结构与篇幅

- 「本周完成 / 进行中 / 下周计划 / 需要协调」四段，没有内容的小节直接删掉，不留空标题。
- 全文 300–600 字。每段要点不超过 5 条，一条一行，动词开头。
- 有数字就写数字（"完成 3 份"比"完成了若干份"有用），没数字别硬造。

## 忌词

不要出现"赋能 / 抓齐 / 闭环 / 常态化 / 全面提升"这类没有信息量的词；不要写"在领导的关心下"这类垫话；不要把计划写成完成（进行中就放在进行中那段）。

清单里还有更细的核对项，动笔前读一次 `references/checklist.md`。
